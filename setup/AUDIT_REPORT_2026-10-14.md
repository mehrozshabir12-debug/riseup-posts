# RiseUp Pakistan — ChatGPT publishing audit and fix (14 Oct 2026)

Audited at 17:05 PKT, 14 Oct 2026. Evidence: Metricool brand 7305396 (read-only `getScheduledPosts`, 14–15 Oct),
GitHub repo history, the handover file and the current master prompt (blob `9d5c23ed…`). Nothing was
published, scheduled, edited or deleted during this audit.

## 1. Summary

**The ChatGPT scheduled task has never created a single Metricool post.** The only ChatGPT post (14:00 petrol)
was created at 13:29 PKT, during the interactive setup session, not by a scheduled :45 run. The runs at
14:45, 15:45 and 16:45 PKT left nothing in Metricool.

The design asks one unattended chat run to do too much with tools that are not built for it: search, verify,
generate a photo, draw text into it, proofread it, render a video, upload binaries and schedule 2–4 posts —
inside a window of 15 minutes, while the repository it is told to follow also says "SYSTEM PAUSED, do not
schedule anything". Any one failure ends the run silently, and the run leaves no trace.

**Fix:** ChatGPT does only the editorial work (find, verify, write a small JSON file). The existing GitHub
workflow renders the approved design with code, hosts the media on public GitHub URLs (the method that
published every post this morning), schedules Metricool, verifies, retries, and raises an alarm when a run
leaves no log.

## 4. New architecture

```
ChatGPT scheduled task (HH:45 PKT)                GitHub Actions "RiseUp Media Manager"          Metricool
──────────────────────────────────                ─────────────────────────────────────          ─────────
0  runs/<slot>.json  "started"  ───commit──▶
1  read Metricool (48 h, drafts, slot free?)  ◀───────────────────────────────────────────────── getScheduledPosts
2  search + verify (2 h, 2 outlets / 1 official)
3  requests/<id>.json (text only) ──commit──▶  validate: sources, freshness, card date,
                                               caption, slot, duplicates, caps
                                               render approved card + Story (template/)
                                               design check → posts/*.jpg → public URL check
                                               results/<id>.json
                                               API mode: create feed (T) + Story (T+5) ─────────▶ scheduled
5  connector mode only: copy payloads ──────────────────────────────────────────────────────────▶ createScheduledPost
7  runs/<slot>.json  real outcome ──commit──▶  :55 watchdog — fails if log missing/"started"
                                               every 15 min: status check, retry only ERROR networks (API mode)
```

**Two modes, chosen automatically:**

* **API mode (recommended, fully unattended):** add GitHub secrets `METRICOOL_USER_TOKEN` and `METRICOOL_USER_ID`
  (Metricool → Account settings → API; requires a Metricool plan with API access). ChatGPT only commits text.
  Publishing, verification and retries no longer depend on ChatGPT at all.
* **Connector mode (no secrets):** ChatGPT waits for `results/<id>.json` (1–3 min), then calls
  `createScheduledPost` with the ready payloads. Verification and retries happen at the next hourly run.

If the ChatGPT task cannot write to GitHub in scheduled runs (P1), the editorial step itself must move
outside ChatGPT: a GitHub Actions cron calling an LLM API (OpenAI or Anthropic key as a GitHub secret) with the
same master prompt. That is a further build, not done here.

* **Instagram:** feed POST (or REEL if decision 3); STORY at T+5. An IG Story ERROR "media is not ready" is retried

* **Stories:** always a separate post 5 minutes after the feed post; never carry text.

## 9. Error handling

| Situation | Action |
|---|---|
| No story passes 2 h + verification | Skip, log `skipped_no_fresh_verified_news` with rejected candidates |
| Slot already has a post (incl. Claude draft) | Skip, `skipped_slot_taken` |
| Run starts late | Publish at now+5 min up to T+15, else `skipped_slot_missed` |
| Request rejected / render failed | Nothing published; errors in `results/<id>.json`; workflow run turns red (e-mail) |
| Media URL not reachable | `failed`, nothing published |
| Network ERROR after scheduling | Retry only that network, now+5 min, max 2 retries; never re-post PUBLISHED/PENDING networks |
| Tool missing / auth error in ChatGPT | `error_tool_unavailable: <tool>`; ChatGPT messages you |
| ChatGPT run did not finish | Watchdog at :55 fails → GitHub e-mail |
