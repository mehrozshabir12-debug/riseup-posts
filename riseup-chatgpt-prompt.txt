0. TIME — DO THIS FIRST, EVERY RUN
----------------------------------
- Get the real current time and convert it to Pakistan time (PKT = UTC+05:00). Call it NOW.
- TARGET SLOT T = the next whole hour after NOW that is one of:
  10:00 11:00 12:00 13:00 14:00 15:00 16:00 17:00 18:00 19:00 20:00 21:00 22:00 23:00 00:00
  (between 00:01 and 09:59 the next slot is 10:00).
- The 23:45 run prepares 00:00 of the NEXT calendar date. That 00:00 post still belongs to the
  RiseUp day that started at 10:00 the day before. RISEUP DAY D = slots 10:00 D ... 23:00 D + 00:00 of D+1.
  All daily counts (15 news, 8 TikTok) are per RiseUp day, never per calendar date.
- RUN LOG path: runs/<calendar date of T>T<HHMM of T>.json. Examples: slot 15:00 on 14 Oct =
  runs/2026-10-14T1500.json; slot 00:00 closing 14 Oct = runs/2026-10-15T0000.json.
- Immediately commit the run log with {"slot": "<T ISO +05:00>", "outcome": "started",
  "run_started_pkt": "<NOW ISO>"}. You will overwrite it at the end (section 7).
- Publication time: T itself. Never schedule anything in the past or less than 5 minutes from NOW.
  If NOW is already later than T−5 min, the post may go at NOW+5 min, but only until T+15 min;
  after that the slot is MISSED: write outcome "skipped_slot_missed" and stop.

2. FIND THE NEWS (web search, every run)
---------------------------------------
- Pakistan news, or world news that directly affects Pakistan (prices, fuel, Pakistanis abroad, cricket ...).
- FRESHNESS (one rule, no exceptions): the article must have been FIRST PUBLISHED, or SUBSTANTIVELY UPDATED
  (new facts/figures, not a re-headline or minor edit), within the 2 HOURS BEFORE T.
  For slot 15:00 that means 13:00–15:00 PKT. A timestamp later than NOW is impossible: re-check the time zone.
- Open the article itself and read its own published/updated timestamp (meta or byline). Convert it to PKT and
  write it with offset, e.g. 2026-10-14T13:10:00+05:00. Do NOT use search-snippet dates, "2 hours ago"
  labels or crawl dates. If you cannot establish the exact timestamp, the source does not count.
- VERIFICATION: either
  (a) 2 articles from 2 DIFFERENT approved outlets, both reporting the same facts, or
  (b) 1 official primary source (a *.gov.pk site, SBP, ISPR, PBS, OGRA, NEPRA, PTA, NADRA, FBR, ECP, PSX,
      PMD, NDMA, PCB).
  Approved outlets (and their domains): Dawn (dawn.com), Express Tribune (tribune.com.pk), Geo News (geo.tv),
  The News (thenews.com.pk), Business Recorder (brecorder.com), APP (app.com.pk), PTV News (ptv.com.pk),
  BBC (bbc.com / bbc.co.uk), Reuters (reuters.com), AP (apnews.com), Al Jazeera (aljazeera.com),
  Arab News (arabnews.pk / arabnews.com). Any other website does not count. The workflow enforces this list.
  A wire story re-published by an outlet (e.g. "Express Tribune (Reuters)") is ONE source, not two.
- Cross-check every name, number, place, price and date between the sources before writing the card.
  Effective dates (e.g. "new price from 16 Oct") are written exactly as the source says.
- Skip: rumours, "sources say", unconfirmed casualty figures, graphic violence, private individuals,
  stories about minors, one-sided political attacks. Politics: neutral and factual.
- Prefer stories that matter to ordinary people: prices, fuel, electricity, jobs, education, weather,
  health, cricket, economy, technology, major national decisions.
- If no story passes ALL of the above: outcome "skipped_no_fresh_verified_news", list the best rejected
  candidates and why in the run log, stop. Never post old news to fill a slot. A skip is a correct result.

Rules the workflow checks automatically (the request is REJECTED if any fails):

5. PUBLISH (connector mode only)
--------------------------------
- Read results/<id>.json. Re-read every 60 seconds for up to 10 minutes until status is not missing.
  status "rejected" or "failed": do not publish; copy its errors into the run log (outcome "error_rejected"
  or "error_render_failed"); you may fix it and commit ONE new request with a NEW id if time allows.
  status "awaiting_publish": continue.
- For payloads.feed, then payloads.story, call createScheduledPost with:
    blogId: "7305396"
    date:   payload.publicationDate.dateTime + "+05:00"      (e.g. "2026-10-14T15:00:00+05:00")
    info:   the payload object EXACTLY as given, as a JSON string.
  Do NOT use mediaFiles. Do NOT generate, download or re-upload any image. The payload's "media" already holds
  the public raw.githubusercontent.com URLs; Metricool copies them itself (this is how every post on
  14 Oct 11:05–13:33 was published).
  Do not change networks, types, text, media, times or autoPublish.
- If the time in the payload is already less than 5 minutes away, move BOTH to NOW+5 / NOW+10 min (same
  dateTime in date and info.publicationDate), only while still within T+15 min.
- Check each response: it must return a post id / plannerUrl. Then getScheduledPosts for T and confirm each
  provider is listed with status PENDING (not ERROR). Write the ids and statuses into the run log.
- Commit receipts/<id>.json:
  {"id": "<id>", "scheduled": "<YYYY-MM-DD HH:MM> PKT",
   "posts": {"feed":  {"metricool_id": 0, "status": {"facebook": "PENDING", "instagram": "PENDING", "tiktok": "PENDING"}},
             "story": {"metricool_id": 0, "status": {"facebook": "PENDING", "instagram": "PENDING"}}}}
  Use only the statuses Metricool returned: PUBLISHED, PENDING, ERROR. Never write PUBLISHED unless Metricool shows it.


6. VERIFY AND RETRY (connector mode; API mode does this automatically every 15 min)
------------------------------------------------------------------------------------
At the start of each run (section 1c) read the previous slot's posts:
- PUBLISHED: record the publicUrl in that story's receipt (edit receipts/<id>.json).
- ERROR: retry ONCE now, at most 2 retries in total per network:
  createScheduledPost with the same payload, providers = ONLY the failed networks, keep only those networks'
  facebookData / instagramData / tiktokData, time = NOW+5 min. Never re-post a network that is PUBLISHED or
  PENDING (that creates a duplicate). Record the new id and "attempts" in the receipt.
  Instagram Story "The media is not ready for publishing, please wait for a moment" is an Instagram processing
  delay: the retry at NOW+5 min is the fix; the media URL stays the same.
  TikTok error 40016 (daily limit) = do not retry TikTok again that RiseUp day.
- Any other ERROR after 2 retries: leave it, report it.
